# 4.3 Modbus RTU

> 本节目标：理解 Modbus RTU 的帧结构、寄存器模型、CRC 和异常响应，能实现主站或从站的基础读写。

## 帧结构

```text
从站地址(1) | 功能码(1) | 数据(N) | CRC16(2, 低字节在前)
```

- 地址 `0` 是广播，从站不回复。
- 地址 `1–247` 是单播从站地址。
- 帧间至少 3.5 个字符时间，用于区分帧。
- CRC 低字节先发送，高字节后发送。

## 常用功能码

| 功能码 | 作用 |
| --- | --- |
| `0x01` | 读线圈 |
| `0x02` | 读离散输入 |
| `0x03` | 读保持寄存器 |
| `0x04` | 读输入寄存器 |
| `0x05` | 写单个线圈 |
| `0x06` | 写单个寄存器 |
| `0x0F` | 写多个线圈 |
| `0x10` | 写多个寄存器 |

## 读保持寄存器

主站请求：从站地址 `0x01`，功能码 `0x03`，起始地址 `0x0000`，数量 `0x0002`。

```text
01 03 00 00 00 02 C4 0B
```

从站响应：

```text
01 03 04 00 64 00 C8 XX XX
```

`04` 表示后面有 4 个数据字节，两个寄存器值分别为 `0x0064` 和 `0x00C8`。

## CRC16

```c
static uint16_t modbus_crc16(const uint8_t *data, size_t len)
{
    uint16_t crc = 0xFFFFU;
    for (size_t i = 0; i < len; ++i) {
        crc ^= data[i];
        for (uint8_t bit = 0; bit < 8; ++bit) {
            crc = (crc & 1U) ? (uint16_t)((crc >> 1) ^ 0xA001U) : (uint16_t)(crc >> 1);
        }
    }
    return crc;
}
```

发送时低字节在前：

```c
frame[len] = (uint8_t)(crc & 0xFFU);
frame[len + 1] = (uint8_t)(crc >> 8);
```

## 异常响应

从站出错时把功能码最高位置 1，并返回异常码：

```text
01 83 02 CRC
```

`0x83 = 0x03 | 0x80`，异常码 `0x02` 表示非法数据地址。

常见异常码：

| 码 | 含义 |
| --- | --- |
| 01 | 非法功能 |
| 02 | 非法数据地址 |
| 03 | 非法数据值 |
| 04 | 从站设备故障 |
| 05 | 确认，处理中 |
| 06 | 从站忙 |

## 超时与重试

- 请求后等待响应超时，通常 100–1000 ms。
- 超时后有限次重试，注意命令是否幂等。
- 广播不等待响应。
- 总线冲突/噪声导致 CRC 错误时，丢弃并重试。

## 常见坑

- CRC 字节序错误。
- 寄存器地址是 0-based 还是 1-based 混淆。
- 功能码和寄存器类型不匹配。
- 帧间静默时间不足。
- 多个主站同时访问没有仲裁。
- 把 32 位浮点拆成两个寄存器时字节序不明确。

## 动手实验

1. 用 USB-TTL 和 Modbus 从站模拟器读写寄存器。
2. 用逻辑分析仪抓取请求和响应，核对 CRC。
3. 构造非法地址，观察异常响应。
4. 实现一个最小 Modbus RTU 从站。
5. 在总线中注入噪声，统计 CRC 错误和重试次数。
