# 0.5 第一个固件：点灯、串口与调试

> 本节目标：完成第一个可烧录、可观察、可断点调试的 STM32 固件。不要急着理解所有 HAL 细节，先把“写代码 → 编译 → 烧录 → 观察 → 调试”的闭环跑通。

## 创建工程

以 `NUCLEO-F411RE` 为例：

1. 打开 STM32CubeMX，选择 `Board Selector`，搜索 `NUCLEO-F411RE`。
2. 启用 `LD2` 对应 GPIO 输出。NUCLEO-F411RE 的 LD2 通常连接到 `PA5`。
3. 启用 `USART2`，模式为 `Asynchronous`，波特率 `115200`，8 数据位、无校验、1 停止位。
4. 确认 USART2 使用 `PA2/PA3`，这两个引脚连接到板载 ST-Link 虚拟串口。
5. 生成 STM32CubeIDE 或 Makefile 工程，编译并烧录。

如果你使用其他板卡，必须以原理图为准确认 LED 和串口引脚，不要照抄引脚号。

## 最小主循环

```c
/* main.c */
uint32_t last_tick = 0;

const uint8_t boot_msg[] = "boot: hello embedded\r\n";
HAL_UART_Transmit(&huart2, boot_msg, sizeof(boot_msg) - 1U, 100U);

while (1)
{
    uint32_t now = HAL_GetTick();

    if ((now - last_tick) >= 500U)
    {
        last_tick = now;
        HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);
    }

    /* 其他非阻塞任务放在这里 */
}
```

这段代码有三个关键点：

- `HAL_GetTick()` 提供毫秒级时间基准。
- `now - last_tick` 使用无符号差值，能正确处理计数器回绕。
- 主循环没有 `HAL_Delay()`，因此可以继续处理其他事件。

## 串口观察

打开串口终端，选择 ST-Link 对应的虚拟串口，配置 `115200 8N1`。复位后应看到：

```text
boot: hello embedded
```

如果使用 `printf`，需要重定向 `_write` 或 `fputc`，并确保链接选项没有禁用半主机。初学阶段建议先用 `HAL_UART_Transmit` 明确发送缓冲区长度，避免格式化输出的隐式开销。

## 断点调试

在 `HAL_GPIO_TogglePin` 前设置断点，启动调试后观察：

1. 程序是否停在断点。
2. `now` 和 `last_tick` 是否按预期变化。
3. `LD2_Pin` 的宏值是多少。
4. 打开寄存器视图，观察 GPIO 端口输出寄存器。
5. 单步执行，确认下一次进入时间差约为 500 ms。

调试器不是“出问题才用的工具”，而是理解代码与硬件对应关系的显微镜。

## 故意制造一个故障

把串口波特率改成 `9600`，但终端仍保持 `115200`，观察乱码。然后：

- 用示波器或逻辑分析仪测量 USART2 TX 波形。
- 估算一个字符的位宽。
- 改回一致的波特率，确认输出恢复。

这个实验能让你理解：串口通信不是“调用一个发送函数就结束”，而是双方必须约定相同的时序和帧格式。

## 常见问题

| 现象 | 排查方向 |
| --- | --- |
| LED 不闪 | 引脚定义、时钟使能、板载跳线、程序是否运行 |
| 串口无输出 | USART 引脚复用、波特率、终端端口、发送长度 |
| 一复位就跑飞 | 启动文件、链接脚本、时钟配置、栈大小 |
| 断点不命中 | 优化等级过高、调试信息缺失、烧录的不是当前 ELF |
| 只能运行一次 | HardFault、看门狗复位、电源不稳 |

## 面试表达

> 我完成过一个 STM32 最小固件闭环：用 CubeMX 配置 GPIO 和 USART，使用 `HAL_GetTick()` 做非阻塞定时，通过 ST-Link 虚拟串口观察启动日志，并用 GDB 断点和寄存器视图确认 GPIO 输出。

这句话比“我点过灯”更能体现工程能力。
