# 6.4 OTA 与回滚

> 本节目标：设计 MCU 的安全 OTA 流程，覆盖镜像格式、双分区、签名、断电恢复和回滚。

## OTA 不是“下载后写 Flash”

完整流程：

```text
检查版本 -> 下载 -> 校验 -> 写入备用区 -> 标记待启动
-> 重启 -> 自检 -> 确认或回滚
```

任何一步失败都必须能恢复到可用系统。

## 镜像格式

```text
magic | version | hardware_id | length | sha256 | signature | payload
```

- `magic`：识别固件格式。
- `version`：防降级/升级判断。
- `hardware_id`：防止刷错板子。
- `length`：限制大小，防止越界。
- `sha256`：完整性。
- `signature`：来源认证。

Bootloader 先验证 header，再验证 payload 签名，最后才跳转。

## 双分区

```text
Bootloader
Slot A
Slot B
Metadata
```

运行 A 时，新固件写入 B。写入完成后更新 metadata，重启 Bootloader 选择 B。

## 启动确认

新固件启动后：

1. 初始化关键外设。
2. 运行自检。
3. 连接网络/上报心跳。
4. 标记 `confirmed`。

如果启动次数超过阈值仍未确认，Bootloader 自动回滚。

## 断电恢复

- 先擦除/写入备用分区，不碰运行分区。
- 每写一块校验。
- metadata 使用双副本 + CRC。
- 断电后重新下载或从已写块继续。
- 保留串口/USB 恢复模式。

## 增量升级

差分升级能减少流量，但需要：

- 精确的旧版本匹配。
- 差分算法和签名。
- 失败后可全量恢复。
- 版本回滚策略。

初学者先做全量 A/B 升级，稳定后再考虑差分。

## 车队管理

- 分批灰度。
- 失败率监控。
- 暂停/回滚。
- 设备分组和硬件版本匹配。
- 升级窗口和电量/网络条件。

## 常见坑

- 只校验 CRC，不校验签名。
- 升级过程中覆盖运行分区。
- metadata 掉电写坏，设备无法启动。
- 没有硬件版本检查，刷错固件。
- 失败后无法回滚。
- 所有设备同时升级，故障扩散。

## 检查清单

- [ ] 镜像有 magic、版本、硬件 ID、哈希和签名。
- [ ] 使用 A/B 分区，运行区不被覆盖。
- [ ] 新固件通过自检后才确认。
- [ ] 断电和启动失败能回滚。
- [ ] 支持灰度发布和暂停。
- [ ] 保留恢复模式。
