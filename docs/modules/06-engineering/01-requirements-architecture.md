# 6.1 需求、软硬件接口与架构

> 本节目标：把模糊需求拆成功能、约束、接口和验收标准，避免“做到一半才发现硬件不支持”。

## 需求分四类

| 类型 | 示例 |
| --- | --- |
| 功能需求 | 每 60 秒采集温湿度并上报 |
| 性能需求 | 端到端延迟 < 2 秒，CPU < 70% |
| 可靠性需求 | 断网缓存 24 小时，看门狗自动恢复 |
| 约束 | 3.3 V 供电，成本 < 80 元，外壳 IP54 |

每条需求都要有验收方式，否则无法判断是否完成。

## 软硬件接口

```text
硬件引脚 -> 电气特性 -> 外设协议 -> 驱动接口 -> 业务接口
```

接口文档至少包含：

- 引脚编号、复用功能、方向、有效电平。
- 电压、电流、上拉/下拉、时序。
- 通信地址、速率、帧格式、超时。
- 错误码和恢复方式。
- 谁负责初始化、谁负责释放、谁拥有缓冲区。

## 架构分层

```text
app/          业务状态机、告警规则
services/     协议、存储、OTA、设备管理
drivers/      传感器、通信、显示
platform/     MCU/RTOS/Linux 适配
bsp/          板级时钟、引脚、电源
```

依赖方向从上到下。上层不直接操作寄存器，下层不包含业务规则。

## 关键设计决策

用 ADR（Architecture Decision Record）记录：

```markdown
# ADR-001 使用 FreeRTOS 而不是超级循环

## 背景
系统有采集、显示、通信和告警四个并发需求。

## 决策
使用 FreeRTOS，任务按数据流划分。

## 代价
每个任务需要独立栈，增加约 6 KB RAM。

## 替代方案
超级循环 + 状态机，RAM 更少，但通信阻塞会影响采集。
```

## 风险清单

- 关键器件交期。
- 传感器精度不达标。
- 无线认证/功耗。
- Flash/RAM 余量。
- 生产测试节拍。
- 现场网络/电磁环境。

## 动手练习

为“低功耗环境监测终端”写一页需求：

1. 功能列表。
2. 性能指标。
3. 硬件接口表。
4. 三个关键风险。
5. 一条 ADR。
