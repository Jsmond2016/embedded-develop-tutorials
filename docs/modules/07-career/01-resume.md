# 7.1 简历改造

> 本节目标：让招聘方在 30 秒内看出你会写代码、懂底层、能做项目，而不是“前端转行试试看”。

## 简历结构

1. 基本信息与求职方向。
2. 技能矩阵（嵌入式优先）。
3. 项目经历（最重要）。
4. 工作经历（突出可迁移能力）。
5. 教育/证书/开源。

## 技能矩阵

```text
语言：C（熟练）、C++（了解）、TypeScript/JavaScript（熟练）
MCU：STM32F4、GPIO/EXTI/TIM/ADC/DMA/UART/I2C/SPI
RTOS：FreeRTOS 任务、队列、信号量、栈预算、故障处理
通信：Modbus RTU、MQTT、TLS、Wi-Fi/BLE
Linux：交叉编译、Buildroot、systemd、libgpiod、内核模块入门
工程：Git、CMake、GDB/OpenOCD、单元测试、CI、OTA
```

不要写“精通 C”除非你能解释指针、内存布局、链接和并发。写“熟悉”更安全。

## 项目 bullet 写法

弱：

> 使用 STM32 做了温湿度采集。

强：

> 基于 STM32F411 + FreeRTOS 设计环境监测节点，使用 I2C 采集 AHT20、DMA 采样 ADC、队列解耦采集/显示/通信；通过栈高水位和看门狗将连续运行稳定性提升到 72 小时无复位。

结构：

```text
做了什么 + 用了什么技术 + 解决了什么约束 + 量化结果
```

## 把前端经验翻译成嵌入式语言

| 前端经历 | 简历表达 |
| --- | --- |
| 性能优化 | 资源受限环境下的性能分析与预算控制 |
| 组件化 | 驱动/业务分层与接口抽象 |
| 微前端/模块化 | 多模块固件架构与依赖管理 |
| 线上排障 | 日志、指标、故障注入与根因分析 |
| CI/CD | 固件构建、测试、产物和发布流水线 |
| WebSocket/MQTT | 设备-云端协议与断线重连 |
| 数据可视化 | 设备管理仪表盘与可观测性 |

## 工作经历怎么写

保留与嵌入式相关的能力：

- 复杂系统设计与跨团队协作。
- 性能/稳定性排障。
- 自动化测试与 CI。
- 代码评审和文档。
- 需求拆解和交付。

弱化纯页面样式、组件库配置等与目标岗位无关的细节。

## 常见坑

- 技能列表全是“了解”。
- 项目没有量化结果。
- 只写“负责”，不写“解决了什么”。
- 把课程项目写成生产项目。
- 简历里出现无法解释的技术名词。

## 检查清单

- [ ] 求职方向明确。
- [ ] 技能矩阵与目标 JD 匹配。
- [ ] 每个项目有约束、方案和结果。
- [ ] 前端经历被翻译成可迁移能力。
- [ ] 简历中每个技术点都能被追问。
