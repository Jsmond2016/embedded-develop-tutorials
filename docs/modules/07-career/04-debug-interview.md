# 7.4 模拟排障面试

> 本节目标：面对开放排障题，能先建立假设、分层定位、设计验证，而不是直接猜代码。

## 回答框架

```text
现象澄清 -> 影响范围 -> 分层假设 -> 观测手段 -> 最小验证 -> 根因 -> 修复与预防
```

## 场景一：设备上电不亮

**先问**：电源灯亮吗？电流多少？串口有输出吗？是否能进入调试器？

**分层**：

1. 电源：电压、电流、短路、保险丝。
2. 时钟/复位：晶振、复位脚、Boot 引脚。
3. 启动：向量表、Flash、Bootloader。
4. 固件：HardFault、看门狗、时钟配置。

**验证**：万用表测电压，示波器看晶振/复位，调试器读 PC，串口看启动日志。

## 场景二：运行几小时后随机复位

**假设**：

- 看门狗未喂或任务饿死。
- 电源跌落/峰值电流。
- 栈溢出/内存越界。
- 温度导致时钟/器件异常。
- 通信异常导致死锁。

**验证**：记录复位原因、运行时间、温度、电流、栈高水位、队列长度；用 GPIO 打点观察任务节奏。

## 场景三：I2C 传感器偶发 NACK

**假设**：

- 上拉不足/上升沿慢。
- 地址冲突。
- 总线被拉低。
- 从设备忙/时钟拉伸。
- 线太长/干扰。

**验证**：逻辑分析仪看 START/地址/ACK/SCL 波形；断开从设备测电平；降低速率；检查上拉。

## 场景四：RTOS 系统卡死

**假设**：

- 死锁/优先级反转。
- 高优先级任务忙等。
- 队列满导致阻塞。
- 中断风暴。
- 栈溢出。

**验证**：暂停调试器看各任务栈和状态；统计 CPU；检查锁顺序；看中断计数；用 trace 工具。

## 场景五：OTA 后设备变砖

**假设**：

- 镜像写入不完整。
- 签名/版本校验失败。
- 启动标志损坏。
- 新固件启动即崩溃。
- 回滚镜像被覆盖。

**验证**：串口看 Bootloader 日志；读 metadata；校验镜像哈希；进入恢复模式重刷；检查分区布局。

## 场景六：设备联网但云端收不到数据

**假设**：

- DNS/TLS 失败。
- MQTT 连接成功但订阅/发布主题错。
- QoS/ACK 未处理。
- 设备时间错误导致证书失败。
- 网关/防火墙拦截。

**验证**：设备端日志、抓包、Broker 日志、`mosquitto_sub` 对照、证书时间检查。

## 面试加分点

- 先问清楚现象和范围。
- 区分“可能原因”和“已证实原因”。
- 每次只改一个变量。
- 保留现场和日志。
- 修复后加回归测试和监控。

## 检查清单

- [ ] 能用分层法拆解开放问题。
- [ ] 能说出每层的观测工具。
- [ ] 不跳过电源、时钟、复位等基础检查。
- [ ] 修复方案包含预防措施。
- [ ] 能结合实际项目讲一次真实排障。
