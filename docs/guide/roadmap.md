# 学习路线

## 总目标

不是成为“会玩开发板的前端”，而是具备嵌入式软件工程师的核心能力：能理解硬件约束、写出可靠的 C 代码、使用 RTOS 组织并发、通过协议连接设备，并用工程化方法交付。

## 四周节奏模板

| 周次 | 学习重点 | 产出 |
| --- | --- | --- |
| 第 1 周 | 概念、工具链、最小实验 | 可编译、可烧录、可调试 |
| 第 2 周 | 原理与代码拆解 | 能解释每一行关键代码 |
| 第 3 周 | 故障复现与排障 | 能定位至少 2 个典型问题 |
| 第 4 周 | 小项目与复盘 | 演示、文档、面试表达 |

## 阶段检查点

### 检查点 A：主机端 C 工具库

不依赖开发板，完成环形缓冲区、命令解析器、状态机和单元测试。通过标准：能在主机上运行测试，能解释内存布局与边界处理。

### 检查点 B：裸机环境监测节点

使用 GPIO、定时器、I2C、UART 和状态机完成非阻塞采集。通过标准：无长时间阻塞，串口命令可交互，异常可恢复。

### 检查点 C：FreeRTOS 监测仪

完成采集、显示、告警、日志和看门狗任务。通过标准：队列通信正确，栈高水位可测，优先级设计有依据。

### 检查点 D：IoT 全链路

完成 MCU → 网关 → MQTT → Web 仪表盘。通过标准：断网缓存、重连、时间同步、OTA 和日志可演示。

### 检查点 E：综合项目

完成需求、架构、原理图、固件、测试、OTA 和交付文档。通过标准：能解释设计取舍，能复现故障并恢复。

## 推荐学习比例

- 40% 读原理、读代码、读手册。
- 40% 写代码、接线、测量、调试。
- 10% 写文档、画图、复盘。
- 10% 面试表达与模拟排障。
