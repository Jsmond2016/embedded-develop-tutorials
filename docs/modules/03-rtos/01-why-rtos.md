# 3.1 为什么需要 RTOS

> 本节目标：理解超级循环的边界，知道 RTOS 解决什么问题、引入什么成本，避免“为了用而用”。

## 超级循环

```c
int main(void)
{
    board_init();

    for (;;) {
        button_poll();
        sensor_poll();
        display_poll();
        protocol_poll();
        watchdog_feed_if_healthy();
    }
}
```

优点：简单、可预测、无任务切换开销。

缺点：当业务变多时，模块之间会互相影响。一个阻塞调用或长计算会拖慢所有功能，难以表达不同优先级和截止时间。

## RTOS 提供什么

- 任务调度：按优先级和阻塞状态选择下一个任务。
- 任务间通信：队列、信号量、事件组、通知。
- 时间管理：延时、超时、软件定时器。
- 资源管理：互斥量、临界区。
- 可观测性：任务状态、栈高水位、运行时统计。

它把“一个大循环”拆成多个可独立阻塞的执行流。

## 什么时候需要

- 有多个周期/事件驱动的功能，响应时间不同。
- 需要阻塞等待通信、传感器或用户输入。
- 需要明确的任务优先级和超时。
- 系统需要长期运行、可观测和可恢复。

## 什么时候不需要

- 功能很少，单一循环足够。
- RAM/Flash 极度受限。
- 团队没有 RTOS 经验，引入后反而增加风险。
- 实时性要求可以用定时器中断和状态机解决。

## RTOS 的成本

- 每个任务需要独立栈，RAM 占用增加。
- 上下文切换有开销。
- 任务优先级、共享资源和死锁需要设计。
- 调试复杂度上升：问题可能与时序有关。

## 任务不是线程越多越好

任务划分应围绕“独立职责和阻塞点”，而不是每个函数一个任务。过多任务会导致栈浪费、调度开销和同步复杂。

推荐先按数据流划分：

```text
采集任务 -> 数据处理任务 -> 显示/告警任务
          -> 通信任务 -> 日志任务
```

## 前端类比

RTOS 任务有点像浏览器中的异步任务，但区别很大：任务有自己的栈、优先级和阻塞状态；调度器是确定性的；共享内存没有自动垃圾回收和事件隔离。
