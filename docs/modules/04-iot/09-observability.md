# 4.9 设备可观测性

> 本节目标：建立日志、指标、事件和远程诊断体系，避免设备“黑盒运行”。

## 三类信号

| 类型 | 回答的问题 | 示例 |
| --- | --- | --- |
| 日志 | 当时发生了什么 | 重连失败、CRC 错误、任务启动 |
| 指标 | 系统整体健康吗 | CPU、RAM、队列长度、重连次数 |
| 事件 | 哪个状态发生了变化 | 上线、离线、OTA、看门狗复位 |

日志适合细节，指标适合趋势，事件适合审计和告警。

## 日志分级

- `ERROR`：功能失败，需要处理。
- `WARN`：可恢复异常，需要关注。
- `INFO`：状态变化、启动、连接。
- `DEBUG`：开发细节，量产默认关闭。

日志包含：

```text
时间 | 级别 | 模块 | 错误码 | 上下文
```

不要在中断里直接打印，使用无锁环形缓冲区或 RTOS 队列，由低优先级任务输出。

## 指标

设备端建议暴露：

- 启动次数、复位原因。
- 堆/栈剩余。
- 队列高水位和溢出次数。
- 通信成功率、重连次数、RTT。
- 传感器读取失败次数。
- 电池电压、温度。
- 固件版本和配置版本。

指标要有时间窗口和最大值，不能只报瞬时值。

## 健康检查

```c
typedef struct {
    bool sensor_ok;
    bool network_ok;
    bool storage_ok;
    uint32_t last_heartbeat_ms;
} health_t;
```

健康状态用于：

- 决定是否喂看门狗。
- 上报设备影子。
- 触发降级或重启。
- Web 仪表盘展示。

## 崩溃与现场

- 保存复位原因。
- 保存 HardFault 关键寄存器。
- 保存最近日志到环形 Flash 区。
- 下次启动上报崩溃摘要。
- 避免崩溃日志无限增长写穿 Flash。

## 远程诊断

- 远程调整日志级别。
- 读取指定模块状态。
- 触发一次性自检。
- 下载诊断包。
- 所有命令需要鉴权和审计。

## Web 仪表盘

前端经验在这里可以直接发挥：

- 设备列表与在线状态。
- 实时曲线与告警。
- 固件版本分布。
- 错误趋势和重连热图。
- OTA 批量任务进度。

但要注意：仪表盘显示的是“数据质量”，不是“看起来漂亮”。失败、延迟、离线必须显式呈现。

## 常见坑

- 日志太多，拖慢系统并写满 Flash。
- 指标只有瞬时值，没有最坏值。
- 设备离线但云端仍显示在线。
- 崩溃后没有现场，无法定位。
- 远程诊断命令没有权限控制。

## 动手实验

1. 为固件增加日志分级和环形缓冲区。
2. 上报 CPU、栈、队列和重连指标。
3. 用 Web 页面显示设备在线状态和趋势。
4. 模拟 HardFault，重启后上报崩溃摘要。
5. 远程调整日志级别并下载诊断包。

## 检查清单

- [ ] 日志、指标、事件职责清晰。
- [ ] 日志不在中断中阻塞输出。
- [ ] 指标包含最坏值和溢出计数。
- [ ] 健康状态能驱动看门狗和降级。
- [ ] 崩溃现场能跨复位保留。
- [ ] 远程诊断有鉴权和审计。
