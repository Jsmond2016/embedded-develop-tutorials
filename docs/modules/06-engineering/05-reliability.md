# 6.5 可靠性与失效分析

> 本节目标：用 FMEA 思维找出最可能失效的环节，并把恢复机制写进设计，而不是等现场投诉。

## 常见失效

| 失效 | 现象 | 恢复手段 |
| --- | --- | --- |
| 掉电 | 配置丢失、文件损坏 | 原子写、双副本、日志 |
| 欠压 | 随机复位、Flash 写错 | BOR、电源监测 |
| 看门狗 | 周期复位 | 健康检查、故障日志 |
| Flash 磨损 | 写入失败、数据损坏 | 磨损均衡、环形日志 |
| 通信中断 | 数据缺失 | 缓存、重试、补传 |
| 传感器漂移 | 数据不准 | 校准、合理性检查 |
| 高温/低温 | 时钟偏差、电池容量下降 | 降额、温度补偿 |

## FMEA

对每个功能问：

1. 可能怎么坏？
2. 影响多大？
3. 发生概率多高？
4. 能否检测？
5. 如何预防/恢复？

优先级可以用 `严重度 × 概率 × 可检测性` 粗略评估。

## 掉电安全

- 配置写入使用双副本 + CRC。
- 先写新副本，校验后再切换指针。
- 关键数据定期 `fsync`。
- 文件系统选择支持断电恢复的方案。
- 保留恢复出厂设置。

```c
typedef struct {
    uint32_t magic;
    uint32_t version;
    uint8_t  payload[64];
    uint32_t crc;
} config_slot_t;
```

两个 slot 轮流写，启动时选 CRC 正确且版本最新的一份。

## Flash 磨损

- 不要高频写同一地址。
- 使用环形日志或磨损均衡。
- 限制日志速率和总写入量。
- 监控擦写次数和写入失败。
- 关键参数变化时才写，不要每秒保存。

## 看门狗与复位

- 复位原因持久化。
- 连续复位计数。
- 多次失败进入安全模式。
- 安全模式下保留通信和恢复能力。

## 环境与认证

- 高低温测试。
- 电源波动/浪涌。
- EMC/ESD。
- 振动、湿热、盐雾（按产品场景）。
- 认证要求尽早确认，不要量产后补。

## 常见坑

- 配置文件只写一份，掉电后全丢。
- 日志每秒写 Flash，几个月写坏。
- 看门狗复位后不记录原因。
- 只做常温测试。
- 失效后没有安全模式。

## 检查清单

- [ ] 关键数据有双副本和 CRC。
- [ ] 配置写入能承受掉电。
- [ ] Flash 写入频率受控。
- [ ] 复位原因和连续失败可追踪。
- [ ] 有安全模式和恢复路径。
- [ ] 做了至少一轮环境和电源异常测试。
