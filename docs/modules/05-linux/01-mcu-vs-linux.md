# 5.1 MCU 与嵌入式 Linux 的差异

> 本节目标：理解 MCU 与嵌入式 Linux 在启动、内存、驱动、实时性和开发方式上的差异，做出合理的平台选择。

## 平台对比

| 维度 | MCU + RTOS | 嵌入式 Linux |
| --- | --- | --- |
| 典型硬件 | Cortex-M，KB 级 RAM | Cortex-A，MB/GB 级 RAM |
| 启动 | 向量表直接进入应用 | BootROM → Bootloader → Kernel → Rootfs |
| 内存 | 静态分配为主，无 MMU | 虚拟内存、进程隔离 |
| 驱动 | 直接操作外设寄存器 | 内核驱动 + 用户空间接口 |
| 实时性 | 微秒级、确定性强 | 通用内核毫秒级，需 RT 补丁 |
| 开发生态 | C、厂商 SDK | C/C++、Python、Go、Node、容器 |
| 升级 | 单固件/双分区 | 整机镜像、包管理、A/B 分区 |

## 什么时候选 MCU

- 低功耗、电池供电。
- 硬实时控制、电机、采样。
- 成本敏感、量大。
- 启动时间要求极短。
- 外设简单、无复杂网络/文件系统。

## 什么时候选 Linux

- 需要网络、文件系统、USB、摄像头、显示。
- 需要多进程、容器、脚本和丰富生态。
- 需要复杂协议栈、数据库或 Web 服务。
- 计算量较大，RAM/存储充足。
- 实时性要求可以用 PREEMPT_RT 或异构架构满足。

## 异构架构

很多产品同时使用 MCU 和 Linux：

```text
传感器 -> MCU（实时采集/安全控制） -> Linux（协议/UI/云端）
```

MCU 负责硬实时和低功耗，Linux 负责复杂业务和联网。

## 学习路径差异

- MCU 重点：寄存器、启动、中断、RTOS、低功耗。
- Linux 重点：交叉编译、启动链、设备树、驱动模型、用户空间接口。

已有 MCU 基础后学 Linux，会更容易理解内核为什么这样抽象。

## 常见误区

- 认为 Linux 一定“更高级”，所有项目都上 Linux。
- 认为 MCU 不能联网，实际上可以用 Wi-Fi 模组/MQTT。
- 认为 Linux 实时性一定差，忽略 RT 补丁和隔离。
- 只会在 Linux 上写应用，不理解驱动和启动链。
