# P3 FreeRTOS 环境监测仪

## 目标

把 P2 的裸机状态机升级为 FreeRTOS 多任务系统，训练任务划分、队列、栈预算和故障恢复。

## 任务设计

| 任务 | 优先级 | 职责 | 阻塞点 |
| --- | ---: | --- | --- |
| health | 5 | 汇总心跳、喂狗 | 1 s 周期 |
| sensor | 4 | 采集并发送样本 | 队列满/周期 |
| comm | 3 | 上报与重连 | 网络/队列 |
| display | 2 | 刷新 OLED | 200 ms 周期 |
| log | 1 | 输出日志 | 日志队列 |

## 数据流

```text
sensor_task -> sample_queue -> display_task
                           -> comm_task -> net_queue
log_queue -> log_task -> UART
health_task <- 心跳计数 <- 各任务
```

## 关键要求

- 所有任务使用静态创建或明确堆策略。
- 每个任务记录栈高水位。
- 队列满时不阻塞关键任务，记录丢弃计数。
- 网络断线使用指数退避重连。
- 任一关键任务心跳超时，停止喂狗并安全复位。

## 故障演练

1. 把 `comm_task` 优先级调到最高并忙等，观察其他任务饥饿。
2. 让两个任务交叉获取互斥量，复现死锁。
3. 把 `display_task` 栈减半，观察溢出钩子。
4. 断开网络 30 分钟，观察队列、重连和缓存。
5. 暂停 `sensor_task` 心跳，观察看门狗复位。

## 验收

- 连续运行 72 小时无复位。
- 最坏 CPU 占用 < 70%。
- 所有任务栈余量 > 20%。
- 断网恢复后数据补传完整。
- 故障演练有记录和修复。

## 交付物

- 任务/队列/优先级表。
- 栈高水位和 CPU 占用报告。
- 看门狗与健康检查设计。
- 故障演练复盘。

## 面试表达

> 我按数据流而不是函数划分任务，用队列解耦采集、显示和通信。健康任务汇总各任务心跳，只有在所有关键任务正常时才喂狗，避免系统卡死但看门狗仍被刷新。
