# 4.8 设备安全

> 本节目标：理解 IoT 设备的主要攻击面，能把“安全”落到启动、通信、存储和升级的具体设计上。

## 威胁模型

先问四个问题：

1. 攻击者能物理接触设备吗？
2. 设备能访问哪些网络和云服务？
3. 最坏情况下会泄露什么、控制什么？
4. 安全事件需要多长时间被发现和恢复？

常见攻击：

- 读取调试口或 Flash 提取密钥。
- 伪造设备接入云端。
- 中间人截获/篡改通信。
- 重放旧命令。
- 上传恶意固件。
- 利用缓冲区溢出远程执行代码。

## 安全启动

启动链路：

```text
BootROM -> 一级 Bootloader -> 应用固件
```

每一级验证下一级的签名/哈希：

- 公钥或根哈希烧录在不可改区域。
- 固件镜像带签名。
- 验证失败进入安全模式，不执行应用。
- 回滚保护防止降级到有漏洞版本。

## 密钥与凭据

- 私钥不应出现在代码仓库、日志或普通 Flash 分区。
- 优先使用安全元件/OTP/受保护密钥区。
- 每个设备唯一密钥，避免泄露一个影响全部。
- 支持密钥轮换和吊销。
- 不要把 MAC 地址当密钥。

## 通信安全

- 使用 TLS 1.2/1.3，校验服务器证书。
- 设备证书或令牌有有效期和撤销机制。
- 时间同步失败时要有安全降级策略。
- 命令带 nonce/序号/时间戳，防重放。
- 服务端做权限校验，不能只依赖设备端。

## 固件升级

```text
下载 -> 校验签名 -> 写入备用分区 -> 标记待启动 -> 重启验证 -> 确认/回滚
```

要点：

- 镜像签名覆盖完整固件。
- 断电恢复后能继续或回滚。
- 版本号单调递增。
- 升级包加密不是必须，但签名必须有。

## 调试接口

- 量产设备关闭或锁定 SWD/JTAG。
- 保留受控的恢复方式。
- 不要在生产固件中保留默认密码和调试后门。
- 日志中不要打印密钥、令牌和完整个人信息。

## 安全编码

- 所有外部输入都做长度和格式校验。
- 不使用 `strcpy`/`sprintf` 等无边界函数。
- 解析器限制最大帧长和嵌套深度。
- 失败时默认拒绝，不要默认放行。
- 关键状态机有超时和重试上限。

## 常见坑

- “先关闭证书校验，量产再开”，最后忘了。
- 所有设备共用同一个密钥。
- OTA 只校验 CRC，不校验签名。
- 调试口在生产板上仍然开放。
- 日志打印 Wi-Fi 密码和云端 token。
- 没有回滚保护，攻击者可降级固件。

## 动手实验

1. 为 OTA 包生成 SHA-256 和签名，设备端验证。
2. 用错误签名升级，确认被拒绝。
3. 模拟重放一条命令，验证 nonce/序号保护。
4. 检查固件日志，清理敏感信息。
5. 制定一份量产安全清单。

## 检查清单

- [ ] 有明确威胁模型和信任边界。
- [ ] 安全启动验证固件签名。
- [ ] 每台设备有唯一凭据。
- [ ] TLS 证书校验开启。
- [ ] OTA 支持签名、断电恢复和回滚。
- [ ] 生产设备关闭调试接口并清理日志。
