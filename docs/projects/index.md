# 项目实战总览

> 项目不是“把例程拼起来”，而是训练需求拆解、接口设计、测试、排障和交付。

## 项目路线

| 项目 | 重点 | 建议周期 | 可展示成果 |
| --- | --- | ---: | --- |
| P1 主机端 C 工具库 | C、测试、构建 | 1–2 周 | 可运行的测试套件 |
| P2 裸机环境监测节点 | GPIO、I2C、UART、状态机 | 2–3 周 | 非阻塞采集设备 |
| P3 FreeRTOS 监测仪 | 任务、队列、栈、看门狗 | 2–3 周 | 多任务固件 |
| P4 IoT 网关 | MQTT、TLS、缓存、Web | 2–3 周 | 全链路 Demo |
| P5 综合项目 | 需求、架构、测试、OTA、交付 | 4–6 周 | 产品级作品集 |

## 通用验收

每个项目都必须有：

- 清晰的 README 和接线说明。
- 可复现的构建命令。
- 正常、边界和错误路径测试。
- 至少一次故障注入和复盘。
- 资源占用记录（Flash/SRAM/CPU/栈）。
- 演示视频或实物照片。

## 评分建议

| 维度 | 权重 |
| --- | ---: |
| 功能完成度 | 30% |
| 可靠性/错误处理 | 20% |
| 代码质量与分层 | 20% |
| 测试与验证 | 15% |
| 文档与表达 | 15% |

## 项目与岗位

- 想做 MCU 固件：重点 P1、P2、P3。
- 想做 IoT/边缘网关：重点 P2、P4、P5。
- 想做嵌入式 Linux：在 P4/P5 中加入 Buildroot、systemd、驱动和 A/B 升级。
