# 7.6 岗位选择与投递策略

> 本节目标：选择匹配度最高的岗位，准备可验证的作品，控制转岗预期和节奏。

## 岗位选择

优先考虑：

- IoT/边缘网关工程师：能复用网络、Web、数据处理经验。
- MCU 固件工程师：底层能力匹配，但竞争更看 C/硬件。
- 测试/自动化工程师：转岗跳板，能接触硬件和产线。
- 应用软件（设备端 Linux）：C/C++/Go/Python + 网络。
- 技术支持/解决方案：需要沟通和排障，适合有产品经验的人。

谨慎选择：

- 要求 5 年以上 BSP/内核经验的岗位。
- 只招硬件工程师但要求画 PCB 的岗位。
- 以“嵌入式”为名，实际做纯前端/测试的岗位。

## 公司类型

| 类型 | 优点 | 风险 |
| --- | --- | --- |
| 大型设备厂商 | 流程规范、量产经验 | 分工细，可能只做一小块 |
| 中小 IoT 公司 | 接触面广、成长快 | 流程不完善、加班 |
| 芯片原厂/方案商 | 底层深、资料多 | 门槛高 |
| 创业公司 | 端到端负责 | 稳定性差、要求全能 |

## 投递材料

- 一页简历，嵌入式优先。
- 作品集链接（GitHub/演示视频）。
- 项目架构图和接线图。
- 测试/排障复盘。
- 针对岗位的定制说明。

不要用同一份简历投所有岗位。把 JD 里的关键词映射到你的项目。

## 面试轮次

常见流程：

1. 简历筛选。
2. 技术一面：C、MCU、项目。
3. 技术二面：系统设计、RTOS/协议、排障。
4. 主管面：项目取舍、协作、稳定性。
5. HR：动机、薪资、到岗时间。

## 转岗叙事

不要说“前端干腻了”。建议：

> 我做了 7 年 Web，擅长工程化、调试和端到端交付。最近两年持续做嵌入式项目，从 C、STM32、FreeRTOS 到 MQTT/OTA 完成了全链路作品。我希望把软件工程能力带到设备端，长期做软硬结合的产品。

## 薪资与预期

- 转岗初期可能降薪或平薪，换取底层经验。
- 优先看团队、产品、导师和成长空间。
- 不要用前端薪资直接对标嵌入式高级岗位。
- 有量产、Linux、汽车/工业经验后，薪资增长空间更大。

## 投递节奏

- 每周 10–20 份精准投递。
- 记录岗位、JD、投递时间、面试反馈。
- 先投匹配度中等的公司练手，再投目标公司。
- 每轮面试后补一个知识缺口。

## 常见坑

- 只投大厂，忽略中小公司。
- 作品集打不开或无法复现。
- 简历夸大“精通”。
- 面试不会讲失败和取舍。
- 因为一次拒信否定自己。

## 检查清单

- [ ] 目标岗位和城市明确。
- [ ] 简历与 JD 关键词匹配。
- [ ] 作品集可在 5 分钟内被验证。
- [ ] 准备了转岗叙事和失败复盘。
- [ ] 有持续投递和复盘记录。
