# 6.6 安全与合规基础

> 本节目标：知道产品安全不是“加个密码”，而是覆盖启动、通信、升级、数据、供应链和生产的系统工程。

## 安全设计清单

- 威胁模型和信任边界。
- 安全启动与固件签名。
- 设备唯一身份和密钥。
- TLS 与证书生命周期。
- 安全 OTA 和回滚保护。
- 调试接口生产锁定。
- 日志脱敏。
- 供应链和构建环境安全。

## 常见标准与要求

具体适用取决于产品和市场，常见方向：

- **IEC 62443**：工业自动化与控制系统安全。
- **ISO/SAE 21434**：汽车网络安全。
- **ETSI EN 303 645**：消费 IoT 安全基线。
- **GDPR/个人信息保护法**：隐私与数据处理。
- **CE/FCC/CCC**：电磁兼容、无线、电气安全等。
- **功能安全**：IEC 61508、ISO 26262（汽车）等。

不要自行宣称“符合某标准”，认证需要公告机构、测试报告和完整过程证据。

## 安全启动与信任链

```text
不可变根 -> Bootloader 签名验证 -> 应用签名验证 -> 安全服务
```

根密钥必须受保护。签名私钥不应在设备或普通构建机上。

## 数据与隐私

- 只采集业务必需的数据。
- 明确保存期限和删除方式。
- 传输和静态存储加密。
- 日志不记录密码、令牌、身份证号等敏感信息。
- 支持用户删除/导出数据（按法规要求）。

## 供应链

- 依赖版本锁定。
- 构建产物哈希和签名。
- 第三方库漏洞跟踪。
- 生产烧录密钥的分发和审计。
- 防止固件被替换。

## 生产安全

- 每台设备唯一密钥/证书。
- 关闭或锁定调试口。
- 安全启动 fuse 一次性烧录。
- 产测模式有退出机制。
- 报废设备的数据擦除。

## 常见坑

- 所有设备同一密钥。
- 关闭 TLS 证书校验。
- 生产固件保留默认密码。
- 调试串口输出敏感信息。
- 签名私钥放进 CI 环境变量但无审计。
- 没有漏洞响应和升级机制。

## 检查清单

- [ ] 有威胁模型和安全需求。
- [ ] 启动、通信、升级均有验证。
- [ ] 设备身份唯一且可吊销。
- [ ] 日志和数据符合隐私要求。
- [ ] 生产调试接口和密钥受控。
- [ ] 明确适用标准，不虚假宣称合规。
