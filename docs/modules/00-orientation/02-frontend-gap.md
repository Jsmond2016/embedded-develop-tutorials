# 0.2 前端工程师的优势、短板和补齐路径

> 本节目标：明确哪些能力可以直接复用，哪些必须重新建立，避免用前端经验“硬套”嵌入式问题。

## 可以复用的优势

### 工程化能力

Git、代码评审、模块拆分、依赖管理、CI、文档和可测试性，在嵌入式同样重要。很多固件项目的问题不是“不会写代码”，而是没有版本、没有测试、没有可复现构建。

### 调试思维

前端调试强调缩小范围、观察输入输出、构造最小复现。嵌入式调试同样适用，只是观测工具从 DevTools 换成串口日志、GDB、寄存器和逻辑分析仪。

### 网络与协议经验

HTTP、WebSocket、JSON、TLS、MQTT 和设备云端交互高度相关。你比传统固件初学者更容易理解网关、设备管理和数据上报。

### 产品与交互意识

知道用户如何操作、状态如何反馈、异常如何提示，这会直接影响设备端的状态机、告警和配网体验。

## 必须补齐的短板

| 短板 | 典型表现 | 补齐方式 |
| --- | --- | --- |
| C 与内存 | 习惯依赖 GC、对象和异常 | 学静态分配、指针、生命周期、错误码 |
| 硬件约束 | 忽略电压、电流、时序和引脚复用 | 读原理图、看数据手册、用万用表 |
| 实时性 | 用 `sleep` 写业务逻辑 | 状态机、定时器、中断、RTOS |
| 并发 | 以为单线程就没有竞态 | 临界区、原子性、ISR 与任务通信 |
| 底层调试 | 只会打印日志 | GDB、寄存器、栈回溯、逻辑分析仪 |
| 可靠性 | 只验证“正常路径” | 故障注入、看门狗、掉电与恢复测试 |

## 四个关键思维切换

### 从对象到字节

JavaScript 里一个对象可以随时创建和丢弃；MCU 里每个字节都要有明确位置。你要开始关心结构体大小、对齐、栈深度和 Flash 占用。

### 从事件循环到中断

浏览器事件循环有运行时帮你调度。中断可以在任意指令边界打断程序，必须遵守短小、可预测、不阻塞的原则。

### 从异常到错误码

嵌入式常用返回值传递错误，而不是抛出异常。错误必须被显式处理，否则设备可能带着故障继续运行。

### 从“能跑”到“可恢复”

设备可能断电、通信丢包、传感器掉线、Flash 损坏。设计时要回答：出错后如何发现、如何隔离、如何恢复、如何留下现场。

## 常见误区

- **把 HAL 当框架 API**：只记函数名，不理解它配置了哪些寄存器。
- **到处动态分配**：在中断、实时任务或长期运行设备中制造碎片和不可预测延迟。
- **用延时代替状态机**：`HAL_Delay(1000)` 会让整个任务失去响应。
- **只看正常数据**：不处理超时、校验失败、总线锁死和边界值。
- **把 Web 性能指标套到 MCU**：嵌入式更关注确定性、内存上限和功耗，而不是首屏时间。

## 动手练习

把下面这段前端逻辑改写成 C 状态机：

```ts
if (isConnected) {
  send(data)
} else {
  queue.push(data)
  reconnect()
}
```

要求：

1. 不能用阻塞延时。
2. 明确 `IDLE`、`CONNECTING`、`ONLINE`、`BACKOFF` 状态。
3. 队列满时返回错误码。
4. 为每个状态写一个可测试的转换函数。
