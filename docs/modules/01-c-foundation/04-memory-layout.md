# 1.4 内存布局

> 本节目标：知道程序的不同部分放在哪里，能读懂 Map 文件，并对 Flash、SRAM、栈和堆做出预算。

## 典型 MCU 地址空间

```text
Flash: 0x0800_0000  ── 向量表、代码、常量、初始化数据初值
SRAM : 0x2000_0000  ── .data、.bss、栈、堆
外设 : 0x4000_0000  ── GPIO、USART、I2C 等寄存器
```

不是所有数据都在同一个地方。理解地址空间，才能看懂启动文件、链接脚本和指针访问。

## 常见段

| 段 | 内容 | 运行时位置 | 是否占 Flash |
| --- | --- | --- | --- |
| `.isr_vector` | 中断向量表 | Flash | 是 |
| `.text` | 代码、字符串字面量 | Flash | 是 |
| `.rodata` | `const` 只读数据 | Flash | 是 |
| `.data` | 已初始化的非零全局/静态变量 | SRAM | 是，初值存在 Flash |
| `.bss` | 未初始化或初始化为零的全局/静态变量 | SRAM | 否，启动时清零 |
| `stack` | 局部变量、函数调用帧 | SRAM | 否 |
| `heap` | `malloc` 动态分配 | SRAM | 否 |

启动时会做两件事：把 `.data` 的初值从 Flash 复制到 SRAM，把 `.bss` 清零。这也是为什么全局变量不能假设上电后是某个随机值。

## 一个内存预算

假设 MCU 有 512 KB Flash、128 KB SRAM：

| 项目 | Flash | SRAM |
| --- | ---: | ---: |
| 应用代码 | 120 KB | 0 |
| 常量表 | 16 KB | 0 |
| 全局状态 | 0 | 12 KB |
| 通信缓冲区 | 0 | 16 KB |
| 栈（主任务 + 中断） | 0 | 8 KB |
| 堆 | 0 | 16 KB |
| 预留 | 20 KB | 20 KB |

不要只看编译成功。发布前要记录 `.text + .data`、`.bss + stack + heap` 以及最坏栈深度，给未来功能留余量。

## 栈和堆

栈用于函数调用、局部变量和中断现场。嵌入式栈通常很小，深递归、大局部数组和格式化字符串都可能造成溢出。

堆用于动态分配，但在长期运行设备中容易产生碎片和不可预测延迟。实时系统优先使用静态分配或固定大小内存池。

```c
/* 不推荐在中断或高频任务中频繁使用 */
uint8_t *p = malloc(256);

/* 更可预测：静态缓冲区 */
static uint8_t s_rx_buffer[256];
```

## 读 Map 文件

链接时生成 `.map` 文件，重点看：

- 每个段的起始地址和大小。
- 哪些目标文件占用空间最多。
- 栈、堆的边界和剩余空间。
- 是否出现重复符号或被强制保留的库。
- `.data` 初值是否正确放入 Flash。

常用命令：

```bash
arm-none-eabi-size firmware.elf
arm-none-eabi-nm --size-sort --print-size firmware.elf | tail -30
arm-none-eabi-objdump -h firmware.elf
```

## 前端类比

前端 bundle 也有代码、静态资源和运行时内存，但浏览器会帮你管理地址和垃圾回收。MCU 没有这层保护：链接脚本决定段位置，栈溢出可能直接覆盖相邻变量，堆碎片可能让设备运行几天后死机。

## 常见坑

- 大数组定义在栈上，导致栈溢出。
- 在中断里使用 `printf`，栈和可重入性都不可控。
- `.bss` 变量被误以为上电为零，但启动代码没有正确清零。
- 堆和栈相向增长却没有留下安全边界。
- 只看编译通过，不看 Map 文件里的剩余空间。

## 动手实验

1. 定义全局零初始化变量、非零初始化变量、`const` 数组和局部大数组。
2. 编译后查看 `.map`，找到它们所在的段。
3. 用 `nm --size-sort` 找出最大的 10 个符号。
4. 把局部大数组改成静态分配，比较栈使用。
5. 人为把栈调小，观察是否出现 HardFault 或数据被覆盖。
