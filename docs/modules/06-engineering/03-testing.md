# 6.3 测试策略与故障注入

> 本节目标：建立从主机端单测到 HIL、老化、断电和故障注入的测试体系。

## 测试金字塔

```text
        现场/认证测试
      HIL 硬件在环
    集成测试（协议/任务）
  主机端单元测试（纯逻辑）
```

底层测试数量多、执行快；顶层测试数量少、成本高。不要把所有验证都留给“上板试试”。

## 单元测试

适合：环形缓冲区、解析器、状态机、CRC、单位换算、错误码。

```bash
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

覆盖率不是目标，但能发现未测试的边界和错误分支。

## 集成测试

验证模块之间：

- 队列是否溢出。
- 中断到任务的数据是否完整。
- 协议请求/响应是否匹配。
- 重连后是否重新订阅。
- 配置变更是否生效。

可以用模拟器、串口回环、虚拟网络或硬件在环。

## HIL 硬件在环

主机自动控制：

- 电源通断。
- 串口/调试接口。
- 传感器模拟。
- 网络断开/恢复。
- 固件烧录和复位。

典型脚本：

```text
烧录固件 -> 上电 -> 等待启动日志 -> 注入传感器故障 -> 检查告警
-> 断网 -> 检查缓存 -> 恢复网络 -> 检查补传 -> 断电重启
```

## 老化与浸泡测试

- 连续运行 24–72 小时。
- 高频采集/通信。
- 反复重连。
- 队列逐渐填满。
- 观察内存/Flash/错误计数是否增长。

浸泡测试能发现泄漏、碎片、日志写满和计数器溢出。

## 故障注入

| 故障 | 验证点 |
| --- | --- |
| 传感器断开 | 是否标记无效、是否降级 |
| I2C 总线拉低 | 是否能恢复 |
| 网络断开 | 是否缓存、是否重连 |
| 队列满 | 是否丢弃并计数 |
| 栈溢出 | 是否检测并安全复位 |
| 断电 | 是否不丢配置/不变砖 |
| Flash 写坏 | 是否有校验和恢复 |

## 测试记录

每次发布记录：

- 测试版本和硬件版本。
- 测试环境。
- 通过/失败用例。
- 已知问题。
- 未覆盖风险。

## 常见坑

- 只测正常路径。
- 测试依赖人工操作，无法回归。
- 没有记录失败复现步骤。
- 测试环境与现场差异太大。
- 只跑一次老化，不分析趋势。

## 检查清单

- [ ] 纯逻辑有主机端单元测试。
- [ ] 关键链路有集成/HIL 测试。
- [ ] 有 24 小时以上老化测试。
- [ ] 至少覆盖 5 类故障注入。
- [ ] 每次发布有测试记录和已知问题。
