# 0.7 建立代码仓库、实验记录与排障日志

> 本节目标：让每一次实验都可复现、可回溯、可展示。嵌入式学习最容易丢失的不是代码，而是“当时为什么这样接、为什么这样改”。

## 仓库结构

建议一个课程仓库同时包含文档、固件和实验记录：

```text
embedded-journey/
├── docs/                 # 原理、接线、实验记录
├── firmware/
│   ├── common/           # 环形缓冲区、日志、错误码
│   ├── bsp/              # 板级初始化
│   ├── drivers/          # 传感器与通信
│   └── apps/             # 各阶段应用
├── tests/                # 主机端测试
├── tools/                # 脚本与调试配置
├── hardware/             # 原理图、引脚表、BOM
└── README.md
```

每个实验至少记录：目标、接线、关键代码、现象、问题、结论。不要把 IDE 自动生成的构建产物提交到仓库。

## 提交规范

使用中文 Conventional Commits，保持一条提交只做一件事：

```text
feat: 增加按键消抖状态机
fix: 修复串口接收缓冲区越界
docs: 补充 I2C 上拉电阻说明
test: 增加环形缓冲区回绕测试
refactor: 拆分传感器驱动与业务逻辑
chore: 更新 OpenOCD 调试配置
```

提交前检查：

- 代码能编译，测试通过。
- 不提交 `.env`、密钥、个人路径和大量二进制产物。
- 提交信息说明“做了什么”，必要时在正文写“为什么”。
- 硬件相关改动附接线图或引脚变化说明。

## 分支策略

个人学习项目不需要复杂流程：

- `main`：始终可构建。
- `feat/<topic>`：新实验或新功能。
- `fix/<topic>`：问题修复。
- 合并前自己复查 diff，保持历史清晰。

## 排障日志模板

```markdown
## 2026-11-03 I2C OLED 初始化失败

### 现象
调用初始化函数返回 NACK，串口持续打印错误码 0x02。

### 环境
NUCLEO-F411RE，3.3 V，PB6/PB7，4.7 kΩ 上拉，100 kHz。

### 假设
1. 器件地址错误。
2. SDA/SCL 接反。
3. 总线被从设备拉低。
4. 上电等待时间不足。

### 验证
- 用逻辑分析仪确认地址帧为 0x78，实际器件应为 0x3C。
- 修改地址后仍失败。
- 测量 SDA 一直为低，断开 OLED 后恢复。

### 根因
模块焊接短路导致 SDA 被拉低。

### 修复
更换模块，重新上电测试通过。

### 预防
新模块上电前先测 VCC-GND 通断，并记录模块地址。
```

这个模板的价值在于训练“假设—验证”的排障方法，而不是凭感觉改代码。

## 实验记录模板

```markdown
# 实验：TIM2 输出 1 kHz PWM

- 目标：使用定时器输出可调占空比 PWM。
- 硬件：PA0、LED、限流电阻。
- 配置：84 MHz 时钟，预分频 84，自动重装 999。
- 现象：占空比 50% 时 LED 亮度约半亮。
- 测量：逻辑分析仪测得周期 1 ms，占空比 50.2%。
- 问题：修改占空比时出现闪烁，原因是先改比较值后改重装值。
- 结论：先更新影子寄存器，再统一生效。
```

## 用 Git 展示能力

面试时，面试官更愿意看到：

- 逐步演进的提交历史。
- 有测试的公共模块。
- 清晰的 README 和接线说明。
- 真实的问题单与修复记录。
- 能解释的取舍，而不是一个“大而全”的最终压缩包。
