# 5.8 部署、只读根文件系统与 OTA

> 本节目标：设计可靠的整机镜像升级方案，理解 A/B 分区、启动标志、回滚和断电恢复。

## 部署产物

一个可交付的 Linux 设备镜像通常包含：

```text
Bootloader
Kernel + DTB
Rootfs
Data partition
OTA metadata
```

版本信息应包含：固件版本、构建时间、Git commit、配置版本和签名。

## 只读根文件系统

```text
/         只读
/data     可写，保存配置、日志、数据库
/tmp      tmpfs
/run      tmpfs
```

好处：

- 断电不易损坏系统。
- 升级是替换整镜像，而不是修改散落文件。
- 设备行为更可复现。

应用要把运行时数据写到 `/data`，并在启动时处理数据格式升级。

## A/B 双分区

```text
Boot
Rootfs A
Rootfs B
Data
```

升级流程：

1. 下载镜像到备用分区。
2. 校验哈希/签名。
3. 写入启动标志，指向新分区。
4. 重启进入新系统。
5. 应用健康检查通过后确认升级。
6. 失败或未确认则回滚到旧分区。

## 启动标志

U-Boot 环境变量或独立分区保存：

```text
active_slot=A
boot_attempts=1
boot_successful=0
```

启动失败达到阈值后，Bootloader 自动切回旧分区。标志写入必须考虑掉电原子性。

## 常见 OTA 方案

- **RAUC**：A/B 镜像升级、签名、回滚。
- **SWUpdate**：镜像/包升级、恢复模式。
- **Mender**：设备管理 + OTA。
- **自研脚本**：简单但容易遗漏回滚、签名和断电恢复。

## 断电恢复

- 镜像先写备用分区，不覆盖运行分区。
- 写入后 `fsync` 并校验。
- 启动标志使用原子写入或双副本。
- 新系统启动后运行自检，再标记成功。
- 保留恢复模式/串口烧录通道。

## 安全

- 镜像签名，Bootloader 验证。
- 版本号单调递增，防降级。
- OTA 服务鉴权。
- 传输 TLS。
- 记录升级审计日志。

## 常见坑

- 直接覆盖运行中的 rootfs。
- 升级后没有健康检查就标记成功。
- 启动标志掉电写坏，设备变砖。
- 只读系统没有可写数据分区。
- 回滚镜像已被覆盖，无法恢复。
- 没有串口/恢复模式。

## 动手实验

1. 为树莓派设计 A/B 分区布局。
2. 用 RAUC 或脚本模拟升级和回滚。
3. 在写入镜像过程中断电，验证可恢复。
4. 让新系统启动失败，观察自动回滚。
5. 记录升级前后版本和健康检查结果。

## 检查清单

- [ ] rootfs 只读，数据分区独立。
- [ ] A/B 分区和启动标志设计完整。
- [ ] 升级镜像有签名和版本检查。
- [ ] 新系统通过健康检查后才确认。
- [ ] 断电和启动失败都能回滚。
- [ ] 保留串口/恢复模式。
