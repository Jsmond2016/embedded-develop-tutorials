# 7.2 作品集建设

> 本节目标：组织一个能让面试官快速判断能力的作品集，包含代码、硬件、测试、演示和复盘。

## 推荐组合

### 项目一：主机端 C 工具库

证明：C 基础、指针、内存、测试、构建。

- 环形缓冲区、命令解析器、状态机。
- Unity/CMock 或自建测试。
- ASan/UBSan。
- CMake + CI。

### 项目二：裸机环境监测节点

证明：GPIO、中断、定时器、I2C、UART、状态机。

- 非阻塞采集。
- 串口命令。
- OLED 显示。
- 故障注入和恢复。

### 项目三：RTOS + IoT 全链路

证明：任务设计、队列、MQTT、OTA、Web 仪表盘。

- FreeRTOS 多任务。
- 断网缓存与补传。
- TLS/MQTT。
- Web 可视化。
- OTA 和回滚。

## 仓库结构

```text
project/
├── README.md
├── docs/
│   ├── architecture.md
│   ├── wiring.md
│   ├── protocol.md
│   └── test-report.md
├── firmware/
├── hardware/
├── tests/
├── tools/
└── demo/
```

## README 必须回答

1. 解决什么问题？
2. 硬件和接线是什么？
3. 如何构建和烧录？
4. 如何运行和验证？
5. 做了哪些测试？
6. 有什么已知问题？
7. 你负责了哪部分？

## 演示材料

- 30–60 秒演示视频。
- 接线/实物照片。
- 架构图和数据流图。
- 关键波形/逻辑分析仪截图。
- 资源占用和测试结果。
- 一次真实故障的复盘。

## 复盘模板

```markdown
## 问题
设备运行 6 小时后死机。

## 定位
日志显示队列持续增长；栈高水位接近 0。

## 根因
通信任务在断网时重试过于频繁，日志任务被饿死。

## 修复
增加指数退避，日志改为环形缓冲，提高日志任务优先级。

## 验证
断网 24 小时测试，队列不再增长，栈余量 > 30%。
```

## 常见坑

- 只有一个“大而全”的压缩包。
- 没有接线说明，别人无法复现。
- 项目没有测试和错误处理。
- 演示视频只拍 LED 闪烁。
- 不会解释为什么这样设计。
- 把教程代码原样当成自己的项目。

## 检查清单

- [ ] 三个项目覆盖 C、裸机、RTOS/IoT。
- [ ] 每个项目有 README、接线、架构和测试。
- [ ] 有演示视频和实物照片。
- [ ] 至少有一个真实排障复盘。
- [ ] 能说清楚自己负责的部分和取舍。
