# 7.5 入职 30/60/90 天计划

> 本节目标：把“会做课程项目”转化为“能在团队和真实产品里交付”。

## 第 1–30 天：看懂系统

- 搭建本地构建、烧录、调试环境。
- 阅读硬件框图、原理图、软件架构和任务模型。
- 跑通现有测试和产测工具。
- 跟一个完整问题单，从复现到修复。
- 记录术语、缩写和模块负责人。
- 不改大架构，先做小修复和文档补充。

产出：环境搭建记录、系统地图、3 个已修复的小问题。

## 第 31–60 天：独立负责模块

- 负责一个驱动、协议或业务模块。
- 补齐单元测试和错误处理。
- 参与代码评审，学习团队规范。
- 做一次故障注入/稳定性测试。
- 能解释模块的资源占用和时序。

产出：一个可独立维护的模块、测试报告、设计文档。

## 第 61–90 天：端到端交付

- 负责一个从需求到上线的完整功能。
- 协调硬件、测试、云端和生产。
- 处理一次现场/产线问题。
- 做版本发布和回滚演练。
- 输出复盘和改进项。

产出：功能交付、发布记录、复盘文档。

## 前三个月要问的问题

- 系统的启动链路和故障恢复流程是什么？
- 哪个模块最容易出问题？为什么？
- 发布一个版本的完整步骤是什么？
- 现场设备如何拿日志？
- 谁负责硬件、云端、生产和认证？
- 代码评审和测试的门禁是什么？

## 避免的坑

- 一上来重构。
- 只看代码不看硬件。
- 不记录问题，重复踩坑。
- 不敢问，自己猜接口。
- 只完成功能，不考虑测试和量产。
- 把“课程项目经验”当“生产经验”。

## 检查清单

- [ ] 30 天内跑通环境并修复小问题。
- [ ] 60 天内独立负责一个模块。
- [ ] 90 天内完成端到端功能交付。
- [ ] 每个阶段有文档和复盘。
- [ ] 能说清系统启动、发布和故障恢复流程。
